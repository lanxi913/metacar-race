## 四、路障出现的影响（这块决定明天的应变）

路障实测位置 (766.5, -88.2)，落在**南侧通道 y≈-88** 上，正好在两个泊位之间的连线偏南 22 m。

- 我们代码里把它登记成 **半径 8 m 的禁区圆盘**（`ctx.dyn_avoid`），A* 规划时会避开。
- 一旦它在南通道上，从 A 泊位去 B 泊位就**不能走 y=-85/-91 这条**，得：
  北上到 y=-46.2 → 东行到 x≈800/815 → 南下到泊位 B，多绕约 60~70 m。
- 如果它出现在**中部主干 y=4.7**（出闸往西那条），则出闸后要改走 y=-46 或 y=24.8。
- 如果它堵在**闸口附近**，那基本无解（闸口是唯一通道），只能等/绕远——这也是我为什么把闸口做成自动推导。

## 五、对我们代码的意义

1. 路线全是 A* 实时算的（`_job → nav_path`），A* 会把 `dyn_avoid` 里的圆盘抹掉再搜，
   所以**路障位置一变，下一次规划自动换路**，不需要改代码。
2. 行驶中每 2 秒查一次动态障碍表，发现新路障就从当前位置重算（`[replan]` 日志）。
3. 路网是规整网格（横 10 条 / 竖 7 组），A* 在有网格的地方几乎总能找到路，
   绕行最长也就多 70 m ≈ 15 s —— 时间余量 117 s 足够。
4. 唯一要小心的是**灯塔 (720,-96) 和吊机 (800,-103)**：自动绕行时如果压着它们走，
   会有一次急刹+擦碰风险；这两处建议保留现在的手调点。

## 六、复现方式

```powershell
# 1) 起场景导出静态数据（约 1 分钟）
powershell -NoProfile -ExecutionPolicy Bypass -File "...\tools\fog\fog_run_dumpmap.ps1" -Seconds 40 -Deliver 0

# 2) 画图 / 摘要
python tools\fog\draw_map.py  <日志目录>\map_dump.json
python tools\fog\map_summary.py <日志目录>\map_dump.json
```
