# speed — 限速行驶（场景元素 09）

面向「限速行驶」这一题的独立入口，目标是把「读限速 → 循迹 → 不超速」做成可复用的骨架。

---

## 1. 实测得分

| 时间 | 场景 | 得分 | 说明 |
|---|---|---|---|
| 2026-10-23 20:36:54 | 限速行驶 | **110.00** | 基础 100 + `\|a\| ≤ 5` 加分 10 |
| 2026-10-23 20:31:59 | 限速行驶 | 110.00 | 固定油门 0.45 版本 |
| 2026-10-23 20:35:08 | 限速行驶 | 98.61 | 自标定早期版本，爬坡阶段超速 0.26 km/h |
| 2026-10-23 20:36:03 | 限速行驶 | 97.18 | 同上，超速 0.52 km/h |

> 结论：**超速是这题唯一的重罚项**（`20 × (v_max − v_limit)`），
> 起步阶段哪怕只冲高 0.3 km/h 也要扣掉 5 分左右。

## 2. 用法

```powershell
# 终端 A：先跑脚本
.venv\Scripts\python.exe -u speed\main.py

# 客户端点「启动场景」（限速行驶）
```

自动化跑分（自动点启动场景）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\auto_scene.ps1 `
  -Script "speed\main.py" -SceneCp "9650,901F,884C,9A76" -SkipAuto
```

`-SceneCp` 是场景名的 Unicode 码点（限速行驶 = `9650,901F,884C,9A76`），
因为 Windows PowerShell 5.1 会按 ANSI 解析 `.ps1`，脚本里不能写中文。

## 3. 参数从哪来（本项目的硬性要求）

| 参数 | 来源 | 是否写死 |
|---|---|---|
| 限速值 | `SPEED_LIMIT_SIGN` 障碍物的 `extra_info`（`SpeedLimit\|20`） | ❌ 现场读 |
| 目标速度 | 限速 × 0.92 | 相对系数 |
| 刹车阈值 | 限速 × 0.97 | 相对系数 |
| 巡航油门 | **在线自标定**：油门慢爬 → 检测车速平台 → 锁住 | ❌ 现场测 |

自标定日志示例：

```
现场读取: 限速 20 km/h @ (-8.2, -46.6)
  目标 18.4 km/h, 刹车阈值 19.4 km/h
== 自标定完成: 油门 0.781 -> 平台速度 17.23 km/h ==
```

## 4. 为什么是「标定后开环」而不是闭环

同一台机器、同一个场景实测：

| 跑法 | 得分 |
|---|---|
| 恒定油门（标定后锁死，全程不刹车） | **110** |
| 闭环补油门 / 点刹维持目标速度 | 97 ~ 100 |

原因：这个仿真的油门响应有滞后，闭环会在 30 Hz 下反复补油门/点刹，
加速度抖动，直接丢掉 `|a| ≤ 5` 的 10 分。

所以正确姿势是 **用现场手段标定开环量，然后开环执行**。

## 5. 代码结构

| 文件 | 作用 |
|---|---|
| `speed/main.py` | 连接场景 → 读限速牌 → 自标定油门 → 循迹巡航 → 输出 SUMMARY |

`AdaptiveCruise` 三个状态：

1. `ramp`：油门按 `ramp_rate` 上爬，同时滑动窗口测速
2. 平台检测：最近 1 s 速度波动 < `plateau_eps` 且已起步，持续 `plateau_hold`
3. `cruise`：油门锁死；若速度反而超过平台值 +0.6 m/s（疑似升挡）则松油轻刹

## 6. 排错

| 现象 | 原因 | 动作 |
|---|---|---|
| 一直「加载中」 | 先开了场景 | 关场景 → 跑脚本 → 再开场景 |
| 得分 97~100 而非 110 | 起步超速 | 看 SUMMARY 的 `v_peak_kmh` 与 `over_limit_kmh` |
| 自标定一直不触发 | 场景太短/太慢 | 调小 `plateau_hold`，或看日志里 `v` 是否真的平稳 |
| 点错场景 | 卡片匹配到相邻行 | 用 `tools/auto_scene.ps1` 的 `-SceneCp`，它按"标题右下偏移"匹配 |
