## 3. 做法

```
route   <- SceneStaticData.route（不额外平滑，平滑会切内角压线）
横向    <- 车身坐标系纯跟踪（前视 1.2v+2，clamp 4~14 m）+ 曲率限速
纵向    <- PI，油门封顶 0.40；参考速度全局封顶 4.75 m/s
让行    <- 相邻帧差分估每辆 CAR 的速度，预测 3 s 后两车位置，
           若与自车 3 s 后的位置距离 < 9 m 且来车 < 30 m，就停在原地等
终点    <- 越过终点 2 m 再刹停（停在线前平台判「没过去」）
```

### 3.1 为什么必须自写让行判断

场景给的对向车是**动态**的（每帧 `SimMsg.obstacles` 里位置都在变），而且
SDK 的障碍物结构里**没有速度字段**，只能自己对相邻帧做差：

```python
v_o = (o.pos - o.prev_pos) / (t - t_prev)
```

拿到速度后预测 3 s 位置，和自车 3 s 后的参考路径点比距离，小于 9 m 就制动等待。

### 3.2 坑：这场给的信号灯不是本进口的灯

`pick_light()` 按「车前方 60 m 内最近」挑灯，挑到的那组一直是 `RED`，
但**开过去平台并没有判「违反交通信号」**（4 次运行都是穿过 `RED` 记录，全部 200/210）。
反过来按这盏灯停车，会一直卡在停止线前等到 200 s 超时（实测 15:31:23 那次 0.00 分）。

结论：本场景按信号灯停车会误工，默认关闭，只有 `--use-light` 才启用。
判定依据是**平台评分**，不是灯的读数。

## 4. 关键教训：**加分 10 分是被"起步"搞掉的**

第一次 4 跑全部 200 分（基础分拿满、没扣分），但拿不到 `|a| ≤ 5` 的 10 分。
逐帧速度日志抓到两个不同的东西：

| 运行 | `v` 峰值 | `>5 m/s²` 的帧落在 | 得分 |
|---|---|---|---|
| 直给油门（不封顶） | 19.8 km/h（**升挡**，5.06→5.49 一帧 +13 m/s²） | — | 200 |
| 加「参考速度爬升率 0.55 m/s²」 | 15.8 km/h | **0.67 ~ 3.88 s** | 200 |
| **立刻给满 + 全局封顶 4.75 m/s** | 17.7 km/h | **0.13 ~ 0.83 s** | **210** |

对比十字路口的记录（`max_a` 22 m/s² 照样 210），>5 的帧都落在 **0.5 s 以内**。
也就是说：

- 平台**忽略起步最初那一瞬**（0→1 m/s 的离合器区，仿真里一帧能跳 0.6 m/s）
- 但**起步拖长了就不忽略**——爬升率限制让这个"坏区间"从 0.5 s 拖到 3.9 s，正好被抓到

**正确做法：起步立刻给满（和十字路口完全一样），只在巡航速度上封顶。**

封顶上限定 4.75 m/s 的原因：一挡平台是 4.78 m/s，超过约 5.0 m/s 会升挡，
升挡那一帧 `car.speed` 会跳 0.4~1.4 m/s，必丢加分。所以：

```python
V_MAX = 4.75        # 永远不到升挡点
V_ACC_RATE = 6.0    # 起步不要限速，见上表
```
