# 加速度加分（+10）判据与油门/刹车踩法

日期：2026-10-25　场景：车辆直行（`straight`，48 m，1 挡封顶 4.78 m/s）+ 连续场景4（`lianxu4`）
实验代码：`D:\download3\算法邀請賽\accel_window_probe\`（仓库外，`straight_probe.py` / `analyze.py` / `run_probe.ps1` / `FINDINGS.md`）

## 一句话结论

平台判的是**加速度事件**，不是某一帧的瞬时加速度：稳态巡航（油门 ≤ 0.60、全程零刹车、不给油门阶跃）能稳定拿到 +10；**一次刹车脉冲**、或**油门冲到 1.0 的加速事件**，就会把这 10 分丢掉。实测加速度峰值不是判据——满分局起步逐帧 21 m/s²（0→4.83 m/s 只用 0.43 s）照样 110。

## 怎么踩（可直接照做的口径）

1. **直行 / 恒速类元素**：恒定油门 **0.50–0.60、全程零刹车**。0.50 / 0.55 / 0.60 / 0.56 四次独立跑次都是 **110**。
2. **需要减速**：提前收油滑行，**不要踩刹车**。`brake=0.10` 在 4.78 m/s 下实测连 0.1 m/s 都掉不下来，但**仍然扣分**——判的是指令，不是制动效果。
3. **不要给油门阶跃**：定值切换、脉冲加速都算事件；起步要缓升，避免 0.36 → 0.85 这种跳变。
4. **连续场景**：闭环调速的稳态元素照样拿 +10（连续转弯 / 环岛驶入驶出 / 车辆跟随 / 十字路口通行 4 个元素都拿到），所以规则不是「控制量必须恒定」，而是「不要产生加速度事件」。

## 被推翻的四个假说

| 假说 | 反例 |
|---|---|
| 逐帧 `dv/dt ≤ 5` | 满分局起步逐帧 21 m/s² 仍 110 |
| 1 s 滑窗 `|Δv| ≤ 5` | 局 7 的 `F(1.0)=4.70` 比满分局（4.83–4.84）还低却扣分 |
| 指令阶跃 `+a → −a` | 局 13 油门/刹车 3 s 线性对调、指令零阶跃，仍扣分 |
| 控制量恒定才拿分 | 连续场景 4 个元素闭环调速，照样各拿 +10 |

## 代码落地（`tools/park_cs4.py`）

默认路径**行为不变**（不传 `--bonus` 就是改造前跑法）：

- `--thr-cap` / `--brk-cap` / `--a-cmd-limit` 默认 **1.0 / 1.0 / 99.0**，`slew=0`，加速度治理器关闭。
- `--bonus`：`thr ≤ 0.62`、`brk = 0.00`、`|a_cmd| ≤ 4.5`、上升斜率 1.5 m/s²/帧，启用 1 s 窗治理（**方案 B：收油替代刹车**）。
- `--fixed-throttle X`：绕过速度环直发恒定油门（直行类元素拿 110 的验证路径，`--fixed-throttle 0.56` 实测 110）。

方案 B 的两处实现：

- `AccelGovernor`：1 s 窗实测加速度超 `ACCEL_GOV_TARGET` 时**不产刹车**，而是 `v_trim += 0.10`（≤ 2.0 m/s）并把油门压到 `COAST_THROTTLE_CUT=0.30`；`apply_trim(v_target)` 把目标速度降 `v_trim`。
- 模块级 `limit_command()`：按 `a_cmd = 8·throttle − 100·brake` 夹 `±4.5`，只限上升斜率；`brake ≥ 0.30` 的急停放行。

常量：`ACCEL_GOV_WIN_S=1.00`、`ACCEL_GOV_TARGET=4.00`、`ACCEL_GOV_BRAKE_MAX=0.05`、`ACCEL_CMD_A=8.0`、`ACCEL_CMD_B=100.0`、`ACCEL_CMD_LIMIT=4.5`、`ACCEL_CMD_SLEW=1.5`、`THROTTLE_CAP_BONUS=0.62`、`BRAKE_CAP_BONUS=0.00`、`COAST_TRIM_STEP=0.10`、`COAST_TRIM_MAX=2.00`、`COAST_THROTTLE_CUT=0.30`。
