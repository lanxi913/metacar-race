# 功能区合规检测（VLA 场景）——实现与口径

本文记录功能区合规检测任务从「完全不知道要干什么」到 950/1000 的全部结论，
以及 `tools/vla_zone_read.py` 的设计依据。所有数字都来自实测跑次（见文末记分表）。

## 1. 任务与评分

| 项 | 内容 |
|---|---|
| 场景名 | `功能区合规检测任务`（`sub_scenes[0].name`，没有「任务1」字样） |
| 时限 | `time_limit = 120 s`（不是 100 s，100 s 那条只属于文本导航任务） |
| 功能区 | `static.vla_extension.regions` 只有一块：`type=FUNCTION_ZONE(2)`、`id=17532`、`pos=(0,0)`、**50×50 m**、`ori=0` |
| 场内车辆 | **6 辆**：4 辆蓝色小轿车、1 辆红色小轿车（不违规，纯干扰）、1 辆三轮车 |
| 车辆数据 | **不进 `msg.obstacles`**（全程 `obs=0`），只能靠相机看；车顶黄牌太小不可读，编号刷在**车门侧面**（白字 `C-0x`） |
| 规则牌 | 入口杆上一块黄底黑字牌：`RU1 不允许蓝色小轿车` / `RU2 禁止三轮车` |
| 位置/编号 | 车辆**位置每局固定**，编号**每局重排**（`C-01`~`C-06` 洗牌到 6 辆车上） |

评分（《VLA场景任务说明与评分规则》§4.3）：

```
RuleScore_r = 2·C_r / (A_r + B_r)
  A_r = 实际违规数（本场景 A_RU1 = 4、A_RU2 = 1）
  B_r = 去重后提交数
  C_r = 报对数（Pred ∩ GT）
边界：A=0 且 B=0 → 1.0；A=0 且 B>0 → 0
总分 = (Σ RuleScore_r) / n × 1000，再扣通用项（>30 km/h −50、|a|>5 −50、碰撞 −100）
```

上报结构（`sim_api.VehicleControl(vla_extension=...)`）：

```python
VLAExtensionOutput(function_zone_result=FunctionZoneResult(
    violations=[FunctionZoneViolation(rule_code="RU1", sticker_ids=["C-01", ...]),
                FunctionZoneViolation(rule_code="RU2", sticker_ids=["C-03"])]))
```

## 2. 读号链路

| 环节 | 做法 | 实测 |
|---|---|---|
| 找车 | YOLOv8n（`cv2.dnn`）当质量闸门：车框 80~560 px、框心在画面 6%~94% | 0.03 s/帧 |
| 读号 | RapidOCR（PP-OCRv4，`intra_op_num_threads=1`）**单线程、整帧直读**，巡航中在线读 | 侧视 2~6 m 得分 0.78~1.00 |
| 采样 | 左右侧相机各 40%、车头 20%（`CAM0_EVERY=5`），5 Hz 取帧 | 每车攒到 1~7 票 |
| 分类 | 号码字块**四周同一条带**的色相中位数：蓝 109~115、红 169~172、绿 32~35 | 六帧真值 5/5 全对 |
| 定类 | 同一编号按**最高分帧**的色相定类（不是多数票）；编号必须落在 `C-01~C-06` 内 | 修掉 542 分那局与 `C-64` 误读 |
| 三轮车 | **不需要专门停靠**：航线给它 4.5 m 侧距，右视相机 3 票 0.99 直读（停靠状态机已删） | r17/r18 实测 |

关键坑（都吃过）：

1. **车顶黄牌不可读**：贴脸 1.2 m 也只有 29~47 px，数字 12~16 px，Windows OCR / RapidOCR / 模板匹配全部失败。
2. **入口那块规则牌也是大块黄色**：早期车头黄块闸门会把它当成车，抢走暂存帧（r14）。
   现在车头相机只按 `CAM0_EVERY=5` 补采样，不再用黄块触发停靠（`car_yellow_blob` 已删）。
3. **OCR 线程与主循环抢 GIL**：默认线程池 + 多 worker 会把主循环压到 1 Hz（r4 只读到 3 个号）。
   真病根是**线程超订**——`RapidOCR(intra_op_num_threads=1)` 整帧 282~308 ms，主循环 p95 33.7 ms、
   零卡顿；默认线程数下同一帧要 588~1461 ms，主循环出现 12 次 >100 ms 卡顿。
4. **裁 ROI 反而更慢**（660~806 ms）⇒ 必须整帧送 OCR，不要裁剪。
5. **航线要给三轮车留侧距**：r16 的东侧航段从三轮车 2 m 处擦过，`brake=0.10` 停不住，直接撞停
   （`|a|=197`、`dt=0.004`）。改成 `x=13` 后侧距 4.5 m，右视相机就能读。

## 3. 时序预算（当前提交版本：单圈 2.6 m/s + 巡航中在线读号）

| 段 | 里程/工作量 | 用时 |
|---|---|---|
| 单圈巡航 @2.6 m/s | 143.5 m（12 航点） | ≈50 s |
| 巡航中在线读号 | 30 帧过闸 / 29 帧 OCR（≈0.65 帧/s，上限 3.6 帧/s） | 与巡航重叠 |
| 停车排空 + 上报 | 队列为空，只等 idle（0.4 s 静默） | ≈5 s |
| **合计** | | **≈55 s**（硬上限 120 s，**余量 65 s**） |

余量足够再跑一圈反向环线（每辆车从左右两侧各看一次），见 `docs/zone-improvements.md` §2.1。

## 4. 跑法（提交版本）

```powershell
cd metacar-race
.\.venv\Scripts\python.exe -u tools\vla_zone_read.py `
  --seconds 124 --phase-a 70 --frame-budget 120 --laps 1 `
  --out ..\accel_window_probe\_vla_ref\runs\vla-zone-read-rNN
```

先起脚本（阻塞等 `connect()`），再在客户端点「启动场景」。`--self-check` 会跑航点、
分类回归和正则回归，不用连场景。

依赖：`onnxruntime`、`rapidocr-onnxruntime`（清华源装）、`ultralytics`（找 `yolov8n.pt`）；
模型在 `accel_window_probe/_vla_ref/models/yolov8n.pt`（6.5 MB，不入库）。

文件：`tools/vla_zone_read.py`（任务本体）、`tools/wp_follower.py`（航点跟随器）、
`tools/probes/`（一路上用来摸场景的探针，不参与正式跑次）。

## 6. 已知天花板

- **加速度 −50 拿不回来**，三条实证：① 起步 1.1 s `|a|=7.3`（指令只有 `thr=0.027`，平台自身瞬态）；
  ② `thr=0.030` + `steer=+0.92` 时 5.5；③ 纯滑行 `thr=0.000` 时仍频繁 5~9（仿真抖动）。
  该扣分**封顶且不累计**，所以正确率才是唯一杠杆，目标 950。
- **漏 1 辆蓝车**：RU1 从 1.000 掉到 0.857 ⇒ −71 分（928.6）。
- **漏三轮车**：RU2 = 0 ⇒ −500 分（450）。
- 兜底「六号全报」= 543，显著差于少报，只在蓝车 <3 时才用。
