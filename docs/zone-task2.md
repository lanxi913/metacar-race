## 2. 与任务一的关键差异（不是文字差异，是"真值条数"差异）

| 项 | 任务一 | 任务二 |
|---|---|---|
| R01 规则 | `RU1 不允许蓝色小轿车` | `R01 不允许红色小轿车` |
| R01 真值辆数 | **4** | **1** |
| R02 规则 | `RU2 禁止三轮车` | `R02 禁止三轮车`（不变） |
| 「兜底六号全报」的代价 | `2·4/(4+6)=0.8`（可接受） | `2·1/(1+6)=0.286`（致命） |

**评分式反解（由 642.86 反推，与任务一 r23 的 0.643 同源）**：

```
RuleScore_r = 2·C_r / (A_r + B_r)
  A_r = 该规则**真实违规辆数**（不是"漏报数"）
  B_r = 该规则**上报条数**
  C_r = 报对条数
FinalScore = (Σ RuleScore_r)/n × 1000
```

对照：真值 1、精确报 1 ⇒ `2/2 = 1.0`；真值 1、报 6（含对的 1 个）⇒ `2/7 = 0.286`；真值 1、报 0 ⇒ `0`。
⇒ **多报一条就多一个分母，宁可少报也不要乱凑数。**

## 3. 代码改动（最小集，任务一行为不变）

`metacar-race\tools\vla_zone_read.py`（+38/−13 行）：

1. `build_violations(summary, min_votes, violator_cls="blue")`：R01 的取车类别由参数决定；R02 仍按 green（三轮车）判。
2. 新增 `--violator {blue,red}`（默认 `blue`）与 `--expect-violators`（默认 4）。
3. 上报段变量 `blue` → `cars`，兜底文案带实读数与车型。
4. `--self-check` 增补参数化回归用例（blue/red 各一条 + 三轮车 R02）。

**任务二跑法（实测 1000 分那一局用的就是这条）**：

```powershell
.\.venv\Scripts\python.exe -u tools\vla_zone_read.py `
  --violator red --expect-violators 1 --min-submit 999 --hard-submit 55 `
  --seconds 100 --laps 1 `
  --out D:\download3\算法邀請賽\accel_window_probe\_vla_ref\runs\zone2-read-r2
```

参数理由：`--expect-violators 1` 让 R01 只要读到 1 辆红车就不再兜底全报；`--min-submit 999` 关掉提前上报，改成"圈跑完按已有票一次上报"，避免只读到第一辆就提交。

## 5. 已知风险（尚未修，全部属"容错"而非"行为"）

1. **三轮车靠角度运气**：r1 只拍到镜像车顶牌 ⇒ R02 掉票；r2 拍到尾门大字 ⇒ 满分。同一份代码、同样的航线。
2. **提交时 OCR 队列未排空**（两局日志均 `idle=False`）：圈末 0.5~1 s 入队的帧可能来不及进票池。
3. **红车每局只有 1 票**（0.83 / 0.91），模糊一帧就整条 R01 归零。
4. **缺号补齐守卫是任务一常量**：`build_violations` 里 `len(missing)==1 and len(cars)>=3`，任务二 `cars`=1 ⇒ 明明只缺三轮车一个号也不会补。

## 6. 工具教训（沿用）

- `cv2.imread` 在中文路径下失败 ⇒ `np.fromfile` + `cv2.imdecode`；写盘 `cv2.imencode` + `Path.write_bytes`。
- 联络表脚本两份：`runs\zone2-probe-r1\montage.py`（解析 `t010.4_cam0.png` 命名）、`runs\zone2-read-r1\mont_grid.py`（按文件名排序，用于 `gate_t0206_cam2.jpg`）。
- 三轮车车顶牌在部分角度是**镜像**，`RapidOCR` 原图会出 `SO-3` 这类假串并被候选集合过滤；水平翻转后 0.97 命中。
