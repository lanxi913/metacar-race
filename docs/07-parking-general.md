# 泊车：从「经验调参」到「几何推导」

> 这篇文章解释为什么 v8 不需要针对每个车位调参，以及换车位/换车型时还差什么。

## 一、问题

v4 版本的代码里有三个常数，换一个车位就废：

```python
ARC_END_Y_FIX = 0.30     # 针对这个车位的补偿
staging = (pos_x, slot_y - R + FIX)   # 假设车位在左、车道沿 -y
```

实测发现，这套参数能拿 210，但**本质是把这个车位"背"下来了**。

## 二、正确的做法：车位坐标系

拿到车位位姿 `(center, ori)` 后建局部系：

```
u = (cos θ, sin θ)        # 车位轴线方向，指向车位开口外
v = (−sin θ, cos θ)       # 横向

a_long = (车 − center) · u     # >0：车在车位外面
a_lat  = (车 − center) · v     # 0 ：车正好在车位轴线上

side = sign(a_lat)             # 车在车位哪一侧
```

## 三、精确对位点（关键推导）

倒车 90° 圆弧（半径 R，满舵）的位移是固定的：

```
Δ = (−R·u + R·side·v)     # 往车位里退 R，同时横向挪 R
```

要让圆弧结束时**正好落在车位中心**，起点必须满足：

```
对位点 = center + R·u − side·R·v
```

也就是：

| 坐标 | 值 |
|---|---|
| a_long | **+R** |
| a_lat | **−side·R** |

v4 的对位点用的是「车道 x」，而车道离车位 5.64 m、R 只有 5.26 m，差 0.38 m
——这就是必须加 `ARC_END_Y_FIX = 0.30` 的原因。**换成精确解，这个常数直接消失。**

## 四、v8 的实现

```python
# 对位点：纯几何
stage_lat = -side * ARC_RADIUS
stage_x = slot_x + ux * ARC_RADIUS + vx * stage_lat
stage_y = slot_y + uy * ARC_RADIUS + vy * stage_lat

# 倒车满舵，转向符号由 side 决定
steer = side

# 车头与车位轴线夹角 < 2° 后转直线，直线段只做航向微调
steer = clamp(1.2 * heading_err)
```

## 五、实测

| 版本 | 常数 | a_long | a_lat | 航向 | 加速度(1s) | 得分 |
|---|---|---|---|---|---|---|
| v4 | 3 个经验常数 | +0.05 | +0.12 | 1.5° | 2.76 | **210** |
| v6 | 0 个（但判据不收敛） | +0.04 | −0.40 | −3.6° | 2.79 | 未测 |
| v7 | 0 个（揉库方向错） | +0.05 | −0.32 | −8.4° | 2.77 | 未测 |
| **v8** | **0 个** | **+0.04** | **−0.23** | **−2.2°** | **2.79** | **210** |

v8 是唯一"既无经验常数、又拿满分"的版本。

## 六、还差什么（换场景时）

| 场景 | v8 能否直接用 | 说明 |
|---|---|---|
| 垂直车位，不同位置 | ✅ 能 | 全部由车位位姿推导 |
| 垂直车位，车位在另一侧 | ✅ 能 | `side` 自动判 |
| 平行泊车 | ❌ 不能 | 需要两段圆弧（Reeds-Shepp），对位点规则不同 |
| 异形/斜坡泊车 | ⚠️ 部分 | 坐标系通用，但斜坡要考虑重力分量 |
| 换车型（R 不同） | ✅ 能 | R 是车辆属性，重新标定一次即可 |

平行泊车的补法：

```
1. 开过车位，停在车位前 L 处（L 由车位长度和车长算出）
2. 倒车圆弧 A（半径 R），转到约 45°
3. 反向圆弧 B，把车摆直
4. 直线倒到车位中心
```

两段圆弧的半径和角度可以解析求解，同样不需要试参数。

## 七、给队友

- 比赛用 `tools/park_v8.py`（已验 210，无常数）
- `tools/park_v4.py` 留作保底（同分，但有常数）
- 写新泊车场景时，先照第 2 节建坐标系，再按第 3 节算对位点，
  **不要一开始就试参数**，试出来的参数换个场景就失效
