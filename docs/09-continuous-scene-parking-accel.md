# 连续场景1：加速度奖励的实测、一次失败尝试与取舍

> 记录时间：2026-10-24
> 对应代码：分支 `feat/continuous-scene`，工具 `tools/park_cs_single_arc.py`
> 结论一句话：**630 分这套配置（单圆弧倒车）不要为了消加速度尖峰去改倒车速度剖面——改了就丢 200 分。**

---

## 1. 结论先行

- 现状：不跳关一把跑完（约 246 s），平台记 **630 分**
  = 直角转弯 100 + 车辆变道 110 + 车辆直行 110 + 连续转弯 110 + 垂直泊车 200。
- 加速度是**独立的 +10 加分项**（每元素 |a| ≤ 5 m/s² 即得），拿不到**不扣**基础分。
  600 基础分 + 5×10 加速度分 = 理论上限 650。
- 拿不到的两个：
  - **直角转弯**：起步瞬态是平台给的，油门只给 0.02–0.04 也报 12–20 m/s²，**改不了**；
  - **垂直泊车**：倒挡油门从 0 直跳 0.16 → −16.6 m/s²，可以改，但见下一条。
- 试过一次"输出限幅"来压这两个尖峰（提交 `5ab6ac9`），结果是 **430 分**：
  垂直泊车整块 200 分没了——限幅改了倒车速度剖面 → 改了倒车弧几何 → 入库终点横向从
  −0.094 m 变成 −0.294 m，车身压出库边线 0.226 m。
- 已回滚（提交 `83c7a29`），当前分支 tip 与 `986123e`（630 那版）**逐字节相同**
  （`git diff 986123e HEAD` 为空）。
- 推荐：**倒车速度剖面一行不改**；要加速度分就只在"直线/缓弯巡航段"做 PID + 斜率限幅；
  直角转弯那 10 分放弃。真正该修的是**入库横向精度**（见 §6）。

## 2. 分数是怎么来的（实测记录）

平台记分页 `https://i-mylab.com/icv/scenedetail.html?id=lianxu` → 场景「连续场景1」→ 训练记录：

| 开始 → 结束 | 得分 | 说明 |
|---|---|---|
| 15:17:12 → 15:21:54 | **430** | 加了输出限幅的那次（`logs\park_cs\20261024-151713`） |
| 15:01:38 → 15:05:45 | **630** | 全流程一次通过（`logs\park_cs\20261024-150138`） |
| 14:58:54 → 15:00:19 | 320 | 到位判据误触发，在 600 m 外挂倒挡，场景被判结束 |
| 14:54:47 → 14:55:22 | 0 | 同上那一类失败 |
| 14:51:52 → 14:53:13 | **200** | 跳关泊车探针（只做垂直泊车，`logs\park_cs\20261024-145153`） |

拆分数：

- `430 = 100 + 110 + 110 + 110 + 0` → 四个行驶元素在，**垂直泊车 0 分**；
- `630 = 100 + 110 + 110 + 110 + 200` → 直角转弯没有加速度分（100 封顶），其余三个拿到，
  垂直泊车满分。

记分页上一个元素拿 0 分时**整行会消失**（不是显示 0），排查时别以为"没跑这个元素"。

### 2.1 复现验证（2026-10-24 15:43:08 → 15:47:19，630 分）

同一份代码（`0abf4cd`，与 `986123e` 等价）在回滚后再跑一次全程，平台仍是 **630**，
两次的入库指标几乎一模一样：

| 指标 | 150138（首次 630） | 20261024-154309（复现） |
|---|---|---|
| 总时长 | 246.2 s | 244.9 s |
| 平台得分 | 630 | **630** |
| 五元素用时 | 26.1 / 7.7 / 12.9 / 151.5 / 47.9 s | 25.5 / 7.6 / 12.8 / 150.4 / 48.4 s |
| `slot_du` / `slot_dv` | +0.294 / −0.094 m | +0.310 / **−0.089 m** |
| `slot_ori_err` | 2.46° | 2.50° |
| `slot_margin` | −0.036 m | **−0.033 m** |

也就是说这套配置的横向落点是可重复的（两次差 5 mm 量级），
**430 那次的问题是限幅引入的，不是随机性**。

## 3. 加速度超限的确切位置

测法：读 `logs\park_cs\<stamp>\park_cs.csv` 的 `speed` 逐帧差分（≈30 Hz），
**排除换挡帧和速度反号帧**（倒车速度是负的，换挡瞬间的差分是假的）。
不要用 `harsh_accel` 事件计数——那里做了 2 s 去抖，131 帧的尖峰会只记成 6 条。

### 3.1 跑次 20261024-150138（630 那版）

| 元素 | 时刻 (s) | 下发指令 | 速度变化 | a 峰 (m/s²) | 性质 |
|---|---|---|---|---|---|
| 直角转弯 | 0.47–2.40 | 油门 0.119 | 0.12 → 1.85（0.06 s 内完成） | **+20.45** | 平台起步瞬态 |
| 直角转弯 | 1.10–1.17 | 油门 0.119 | — | +12.9 | 同上 |
| 直角转弯 | 1.77–1.90 | 油门 0.119 | — | +7.47 | 同上 |
| 垂直泊车 | 219.07–219.37 | 刹车 0.15 | 5.28 → 3.50 | **−7.7** | 对准段目标速度一步压到 2.2 |
| 垂直泊车 | 232.17 | 刹车 0.12 | 0.32 → 0 | −5.09 | 停车 |
| 垂直泊车 | 233.20–233.50 | 换倒挡，油门 0 → 0.16 | −0.13 → −1.75 | **−16.55** | 命令直跳 |

### 3.2 跑次 20261024-151713（加限幅那版）

| 元素 | 时刻 (s) | 下发指令 | a 峰 | 说明 |
|---|---|---|---|---|
| 直角转弯 | 0.53–1.37 | 油门 **0.04** | +11.97…**+20.24** | 限幅压不住，平台自己甩 |
| 直角转弯 | 6.77–6.97 | 油门 0.85（追 8 m/s） | +9.6…+13.2 | 我们的闭环 |
| 垂直泊车 | 218.3 | 刹车 0.10 | −5.2…−5.5 | 接近段 |
| 垂直泊车 | 232–236 | 倒挡油门 0.04↔0.10、刹车 0↔0.06 来回切 | −4.5…−9.7 | 限幅后仍在 5 上下抖 |

结论：**起步瞬态和平台绑定**（同一份 CSV 里 0.02 油门也能给出 12 m/s²），
可控的只有两类——巡航段的闭环抖动、倒挡启停的命令阶跃。

## 4. 修复尝试 1：输出层限幅（提交 `5ab6ac9`）——代价 200 分

做法（`tools/park_cs_single_arc.py` 新增 `DriveOut`）：

- `thr_up=0.010 / thr_down=0.030 / brk_up=0.010 / brk_down=0.040`（每帧速率限制）；
- `BRAKE_CAP = 0.10`（实测 decel ≈ 1.2 + 24·brake，0.10 约 3.6 m/s²）；
- 换挡后 1.5 s 内油门封顶 0.04（软起步）；
- 所有 DRIVE/REVERSE 命令统一过这层，PARKING 例外。

同一天两次全程跑对比：

| 指标 | 150138（无限幅） | 151713（有限幅） |
|---|---|---|
| 平台得分 | **630** | **430** |
| 时长 | 246.2 s | 248.2 s |
| 入库纵向 `slot_du` | +0.294 m | +0.158 m |
| 入库横向 `slot_dv` | **−0.094 m** | **−0.294 m** |
| 车身出库线 `slot_margin` | −0.036 m | **−0.226 m** |
| 直角转弯 a 峰 | 20.45 | 20.24（没救） |
| 垂直泊车 a 峰 | 17.06 | 10.76（降了但还 > 5，没加分） |
| 车辆变道 a 峰 | 3.94 | **5.45**（变差，临界） |
| 连续转弯 a 峰 | 4.67 | **5.55**（变差，临界） |

也就是说：**限幅没有换来任何一分，还把 200 分弄丢了，并且让两个本来安全的元素贴上 5 m/s² 红线。**

根因：倒车段的速度剖面**直接决定倒车弧的曲率历程**，从而决定入库终点的横向落点。
这个车模的转向响应和速度耦合——同一套 `steering` 指令，在不同速度下走过的空间曲线不是同一条
（实测两次跑在相同的准备点、相同航向角下，横向位置已经差 0.2 m）。

所以「为了消尖峰而放缓倒车」不是优化，是**换了一条停车轨迹**。

## 6. 推荐方案

### P0：保持现状，别再碰倒车段

当前验证过的泊车策略（`tools/park_cs_single_arc.py`）：

- 沿赛道开到车位，**开过车位 `STAGE_PAST_M = 5.57 m`** 后刹停、等 0.8 s；
- 挂 R，`steering = clamp(REVERSE_STEER_SIGN * heading_error / 30, ±1)`，
  `heading_error = wrap(slot.ori_z − yaw)`，`REVERSE_STEER_SIGN = −1`；
- `REVERSE_THROTTLE = 0.16`，超过 `1.20 m/s` 踩 `REVERSE_BRAKE = 0.20`，
  距车位中心 `≤1.50 m` 改 `REVERSE_CREEP_THROTTLE = 0.04` 爬行；
- 到位判据 `dist ≤ 0.35 m` 且 `|heading_error| ≤ 8°` 且 `|v| ≤ 0.30` → 挂 P 保持 8 s。

验收指标（每次跑完必看 `park_cs.csv` 末段）：

| 指标 | 及格线 | 630 那次 | 430 那次 |
|---|---|---|---|
| `slot_dv` 横向 | ≤ 0.10 m | 0.094 | 0.294 |
| `slot_ori_err` 航向 | ≤ 3° | 2.46° | 2.22° |
| `slot_margin` 车身出线 | ≥ −0.05 m | −0.036 | −0.226 |

### P1：想要那 +10，只动巡航段

- 只在**直线/缓弯巡航段**做速度闭环：PID（带抗饱和）+ 加速度斜率限幅（≤3 m/s²/s）；
- **倒车段一行不改**——它的速度就是它的几何；
- 先跑跳关探针（77 s，只做垂直泊车）验证几何没变，再跑全程（248 s）。

### P2：直角转弯的 +10，放弃

实测油门 0.02–0.04 也报 12–20 m/s²，是平台起步瞬态。想拿这 10 分与其调控制，
不如想"这个元素能不能不从静止起步"，成本远高于收益。

### P3：真正该修的——入库横向精度

现在的横向落点靠"对位常量 + 单圆弧"打动，跑次之间差 0.2 m 就会丢 200 分。
**这才是当前最大的风险**，比加速度重要得多。下一步应该把停点做成闭环：

- 倒车过程中用 `slot_dv` 做反馈（例如给航向目标加一个 `k·dv` 的偏置），
  让弧线末端收敛到 `dv ≈ 0`，而不是靠常量对位；
- 或者到位判据改成"`|dv| ≤ 0.10` 才允许 hold"，不满足就做一次小幅度修正；
- 用 `slot_margin`（车身四角 vs 车位框）做最终验收，它比 `slot_dv` 更接近平台判据。

## 8. 给队友的坑

1. **加速度别用事件计数**，用 `frames.csv` 的 `speed` 差分，并排除换挡帧、速度反号帧。
2. 平台回传的 `gear` 就是下发的挡位，换挡那一帧的"速度差"是假的加速度。
3. 记分页上 0 分的元素整行消失，只能靠"总分少了多少"反推。
4. **垂直泊车是"过/不过"**，没有中间分：横向差 0.2 m 就从 200 变 0。
5. 倒车速度剖面 = 停车几何，**不要用它去换加速度分**——我们已经用 200 分买过一次教训。
