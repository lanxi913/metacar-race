## 1. 提交版本

```powershell
.venv\Scripts\python.exe -u vla_park_rapid.py `
  --offset -3.0 `
  --seconds 95 `
  --pulse --v-high 3.8 --v-low 2.8 `
  --laps 1 `
  --min-score 0.6
```

| 参数 | 值 | 说明 |
|---|---|---|
| `--offset` | `-3.0` | 禁停区矩形向内 3 m 贴边 |
| `--pulse` | on | 松油滑行到 2.8 m/s 再给小油门，稳态约 3.6~3.8 m/s |
| `--v-high/--v-low` | 3.8 / 2.8 | 脉冲上下限 |
| `--laps` | 1 | 只跑一圈 |
| `--min-score` | 0.6 | 提交阈值 |

## 3. 为什么能 1000

1. **贴边 3 m**：车与路线距离近，侧贴纸像素足够；
2. **脉冲滑行**：不踩刹车，避开平台「加速度 −50」；速度比恒定油门 4.78 低，单帧覆盖更多；
3. **只用左相机 cam2**：顺时针绕圈时车在左侧，避免三路相机轮换把每路摊到 1/3；
4. **RapidOCR 整帧、单线程**：`intra_op_num_threads=1`，不裁 ROI；
5. **编号归一化**：`D/O→0`、`8→6`，只接受 `B-01~B-06`，避免 `B-020`、`B-81` 这类误读；
6. **阈值 0.6**：那趟 4 个真号最低 0.6 左右，0.75 会漏掉第 4 个；但低票假号也会被放进来，需要靠下一轮的票数/范围过滤。

## 4. 稳定性

同一套配置在不同局会读到 3~5 个号，分数在 700~1000 之间波动：

| 局 | 提交 | 平台分 |
|---|---|---|
| 71455 | 4 报 4 对 | **1000.00** |
| 71451 | 4 报 3 对 + −50 | 700.00 |
| 71435 | 3 报 3 对 | 857.14 |
| 71430 | 4 报 3 对 | 750.00 |

平台取最好成绩，因此 1000 已锁定；正式比赛建议保留 0.6 阈值 + 编号范围过滤，并视现场情况在 0.6~0.75 之间取一个。
