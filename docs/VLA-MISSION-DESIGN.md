# VLA 停车区任务——**一圈 + 读到就偏出去 + 回到线上**的合并状态机（三层规格）

> 把子任务一（贴边一圈）与子任务二（读号交卷）**拼成一条链**，共用同一套三层结构。
> 关键设计选择：**不换路线**。读号不是"另开一条轨迹"，而是把**同一条贴边参考线的横向设定值**临时改掉：
> `e_lat_target: 0 → ±4.6 m → 0`。这样"偏出去/回来"就是一次设定值的平滑斜坡，不存在两套路径打架。
> 文档：本文件；代码骨架：`vla_mission.py`（复用 `vla_stack.py` 的算法层与 `vla_read.py` 的读号层）。

## 0. 一张图看清三层的落点

```
             ┌────────────────── ① 逻辑链（固定顺序，每帧一次）──────────────────┐
   cam0 ───► │ perceive → locate → assess → select →（设定 e_lat_target）→ decide  │
   pose ───► │            ↑          ↑         ↑          ↑                       │
             └────────────┼──────────┼─────────┼──────────┼───────────────────────┘
                          │          │         │          │
              ② 决策层：L0 安全 > L_read 读号机动 > L1 贴合 > L2 节奏
                          │          │         │          │
             ┌────────────┴──────────┴─────────┴──────────┴────────────┐
             │ ③ 算法层：圆角参考线 / 投影 / 曲率 / 前馈+反馈 / 走廊 / 反投影 / OCR │
             └───────────────────────────────────────────────────────────┘
```

三层之间只有数据：算法层是纯函数，决策层输出唯一一组 `(v_t, steer, thr, brk, e_lat_target)`，
逻辑链负责顺序与降级。

## 1. 逻辑链（Chain）

| 步 | 输入 | 输出 | 降级 |
|---|---|---|---|
| perceive | cam0 | `Corridor` + `[CarBox]` | 无图 → 走廊当畅通；不产新车 |
| locate | pose | `i, e_lat, e_head, κ, s_along` | 投影丢 → 沿用上帧 `i`，记 `lost_track` |
| assess | `CarBox`+位姿+`regions` | `CarObs.p_v` | 无区域 → 0.5 |
| select | 候选+已读+剩余时间 | `(target_key, e_lat_target, mode)` | 预算不足 → 清空 setpoint 回 0 |
| decide | 上面全部 | `Decision` | 见第 2 节 |
| actuate | `Decision` | `VehicleControl`（**永不 REVERSE**） | — |
| log | 全量 | `run.csv` + `decision.jsonl` | — |
| submit | 清单 | 一次性 `VLAExtensionOutput` | 提交即结束 |

## 2. 决策层：五个状态，进出条件全部是"当场测出来的量"

| 状态 | 进入条件 | 动作 | 退出条件 |
|---|---|---|---|
| **follow** 贴边巡 | 默认 | `e_lat_target = 0`；`v ≤ 2.5`（弯 1.7） | ①出现候选且 `prize>0.25` 且 `s_ahead ≤ 22 m` → **offset_out**；②`should_submit` → **submit** |
| **offset_out** 偏出 | 见上 | `e_lat_target` 以 **0.35 m/s** 斜坡推向 `±(d_ref − e_ref) = ±4.6 m`（符号 = 目标车在我哪一侧） | 到位（`‖e_lat − target‖<0.25`）或耗时 >4 s → **pass**；中途被判"目标不可能入窗"（距离 <3.5 m 且仍在逼近）→ **offset_in** |
| **pass** 侧向掠过 | 到位 | `e_lat_target` 保持 ±4.6；`v ≤ 2.0`；持续跑 OCR（每帧至多一次） | 读成（`≥0.60` 且形态合法）→ 记票 → **offset_in**；掠过 6 m 仍读不成 → 记 `inaccessible` → **offset_in** |
| **offset_in** 回线 | 见上 | `e_lat_target` 以 0.35 m/s 斜坡回 0，同时 `v ≤ 2.0` | 回到 `‖e_lat‖<0.3` → **follow** |
| **submit** 交卷 | `should_submit` | 停稳（`brk` 斜坡 → 1.0、P 挡）后提交一次 | 场景结束 |

### 2.1 优先级（冲突时谁赢）

```
L0 安全（走廊 gap<12 → 降速 1.4；gap<7 → 0.8；一律不倒车）
  > L_read 读号机动（把 e_lat_target 推出去/收回来）
    > L1 贴合（K_c 闭环把车压到 e_lat_target 上）
      > L2 节奏（曲率限速，只削上限）
```

**读号机动期间安全照旧生效**：如果偏出去的路上被别的车占了，`gap` 变小 → 直接降速甚至放弃本次（转 **offset_in**），绝不为读号冒险。

### 2.2 三条"不许"（防止又退化成记忆题）

1. 不许出现时刻表：状态里没有任何 `t < 3`；
2. 不许出现地名：没有"西南角""第二个车位"之类；
3. 不许有倒车通路：`REVERSE` 在整条链里零引用。

## 3. 算法层：为什么"偏出 4.6 m"就是读号机动

### 3.1 横向设定值的物理意义

贴边线 = 距边界 `e_ref = 1.85 m`（车宽/2 + 0.90）。
读号需要 `d_ref ≈ 6.5 m`（`p_read` 峰值区，f2 实测）。
两者差值就是机动幅度：

```
Δ = d_ref − e_ref = 6.5 − 1.85 = 4.65 m      → 取 4.6 m
e_lat_target = ±4.6 m（符号 = 目标车相对我的左/右）
```

### 3.2 三个控制式（与子任务一相同，只是换了设定值）

```
航向：e_head = wrap180(yaw_ref − yaw)
横向：e_lat_err = e_lat − e_lat_target            ← 唯一变化的地方
舵角：steer = atan(L·κ)/δmax + K_h·e_head + K_c·e_lat_err
慢响应：|Δsteer|≤0.015/帧、低通 0.7/0.3、设定值斜坡 ≤0.35 m/s
```

设定值斜坡 0.35 m/s + 车速 2.0 m/s ⇒ 4.6 m 横向机动需要约 **13 s 纵向时间**（≈26 m 路程）。
这就是"提前量"的来处：**必须在候选前方 22 m 触发**，否则还没偏到位就错过了（22 m ÷ 2 m/s ≈ 11 s ≈ 到位所需时间）。

### 3.3 时间账（动态算，不写死）

```
一圈 ≈ 周长 128 m ÷ 2.4 m/s ≈ 53~62 s
每辆读号 ≈ 偏出(11 s) + 掠过(3 s) + 回线(11 s) − 与巡线重叠 ≈ 18~22 s
候选数 N 由现场决定（一圈里 `p_v>0.5` 的数量），预算允许则读 `min(N, floor(剩余/22))` 辆
交卷 ≈ 3 s     硬底线 0.90 × 100 s
```

若一圈就"信息饱和"（都定案）→ 直接交卷，省掉补拍。

## 4. 失败模式与兜底

| 失败 | 触发 | 兜底 |
|---|---|---|
| 读不到 | 掠过 6 m 仍 `score<0.60` | 记 `inaccessible`，**不报**（宁漏不误） |
| 偏不出去 | 4 s 未到位 | 放弃本次，回线继续巡 |
| 偏出去被挡 | 走廊 `gap<7` | 立即回线，降速 |
| 同一 id 两辆车 | 投票冲突 | 两辆都不报 |
| 时间不够 | `剩 < 13 s` | 停稳 → 交卷（有票就报） |
| 投影漂移 | `lost_track` 连续 30 帧 | 停用视觉候选，只巡线，按已有票交卷 |

## 5. 验收（分三层验，不需要每次都上真车）

| 层 | 验什么 | 手段 |
|---|---|---|
| 算法 | 圆角线投影/曲率/OCR | 离线帧与运动学模型（`vla_stack_sim.py` 已就绪） |
| 决策 | 五个状态切换是否都由量触发 | 回放 `run.csv`：把状态序列与 `e_lat_target` 画出来看是否平滑、是否卡在某个状态 |
| 逻辑链 | 交卷清单与人工核对一致 | dry-run：真车跑一圈但**不提交**，只输出清单 |

真车跑之前的三道闸：①离线五项指标 PASS；②回放状态序列无"卡死/来回抖"；③dry-run 清单核对一致。
