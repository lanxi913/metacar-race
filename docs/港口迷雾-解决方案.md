# 港口迷雾 —— 解决方案（可执行的技术方案）

> 配套《港口迷雾-规划书.md》。这份只讲**怎么做**：分工、调度、每个得分项的算法、状态机、参数表、以及在现有 `fog_mission.py` 上要改哪几处。

---

## 一、总体架构：一个主循环，四辆车各自一个「车道保持控制器」

```
                   ┌──────────────── 主循环 (10 Hz) ────────────────┐
  全局任务图(DAG)  │  任务调度器 Scheduler                          │
  signals→scan→    │   ├─ 车辆代理 CarAgent{A,B,C,D}                │
  cross(A,B)→      │   │    状态: IDLE/RUN/HOLD/DONE                 │
  berthA/B         │   │    执行: LaneDriver(稠密航点+纯跟踪)        │
                   │   └─ 事件源: 观测/凭证/等级/任务态               │
                   └───────────────────────────────────────────────┘
```

- **一个 socket、一个主循环**：所有车的控制都在同一个 10 Hz 循环里下发（`set_vehicle_control` 每车一条），**不要用线程并发写 socket**。
- 每辆车一个 `LaneDriver`（已有）：稠密航点（车道中心线每 2 m 一点）+ 纯跟踪 + 卡死自救 + 掉头。
- 任务调度器只负责「谁现在该去哪、谁该等」，**不产生运动指令**。

### 为什么要这样改（现状问题）

现有 `fog_mission.py` 是**阶段串行**：`stage_signals → stage_scan → stage_cross → stage_deliver`，每个阶段内部再按车串行等待。结果：
- 运输车在信号阶段（175 s）**完全闲置**；
- 过路口时两车各花 ~100 s 赶路；
- 泊位阶段 A 交完就 430 s，B 只剩 170 s，观测窗口一错过就完蛋。

改成「预就位 + 事件驱动」后，同样的路，总时长从 ~600 s 压到 **~330 s**。

## 二、四个得分项的具体做法

### 2.1 现场信号（240 分）——已完全打通

```
while 未拿到 A/B/C:
    开到距信号 ≤6.0 m 的车道上（按 SIGNALS 表）
    每帧读 get_observation 里该 object 的 (distance, state, hint)
    一旦 state == "key_visible"：立刻 interact(vid, sig, "submit_key", {"key": KEY})
        ← 必须滑行中提交；停下再交会 not_available
    成功后顺序推进 A→B→C（B 依赖 A、C 依赖 B）
```

- Key 用正则 `KEY[- ]?([A-Za-z]\d{1,3})` 从 `hint` 里抓。
- 三车的信号坐标固定（见规划书第三节），**不需要探索**。

### 2.2 封闭道路扫描（160 分）——已打通

```
信号 C 验完后：Car_C 已在灯塔旁 → creep_to(距 Roadblock_East 8.5 m) → 停稳
interact("Car_C", "Roadblock_East", "scan")          # 不传 payload！
→ granted: "Roadblock scanned and reroute issued."，phase: Roadblock → Intersection
```
成功后可拿到 `position=(766.47,-88.22)`，立刻把它 ±7 m 带写入栅格禁行掩膜。

### 2.3 中央路口通行（2×100）——已打通，关键是「贴中心线」

```
入场：车先停到入口车道（南口 (731,-31) / 北口 (728.8,6)），v<0.8 时开始
      每 0.6 s 试 request_entry（要求：距中心 ≤12 m 且在进车道内）
获批：不调头，沿 **x=728.79 的显式折线**（不是车道航点）直穿
      每跨 5 m 试一次 release，读四种报错定位自己处在哪一段
成功：到 (728.8,-9.7~-9.9) 时 release 返回 granted=True "Intersection released."
```

**四种报错 = 位置指示器**（实测）：

| 报错 | 含义 | 该做什么 |
|---|---|---|
| `not on an eligible intersection approach` | 不在进车道或距中心 >12 m | 回到入口车道再申请 |
| `has not entered the intersection after receiving access` | 还没进 6 m 区 | 继续往前 |
| `has not physically cleared the intersection` | 进了没出去 | 继续穿过 |
| `has not reached a connected intersection exit` | 出口侧错 | 换对侧出口 |
| `granted=True` | 成功 | 记录 +100 |

铁律：**未获批绝不进 6 m 区**（m18 因此整局归零）。

### 2.4 指定车位停靠（2×200）——A 已成，B 差「停稳确认」

#### (1) 先让泊位到 lv3（精确定位）

规则原文：**「信号齐备时可直接提升至精确等级，不要求逐级重新提交观测」**；升级需要「两辆不同车辆的合格观测」，且
- 目标在 **≤30 m** 且有视线（泊位实际要更近，见下表）；
- 两观测点间距 **≥ 5.30 m**（Cargo 车长）；
- 两次观测 **时间跨度 ≤30 s**；
- **同一辆车在同一等级只发一次 `observation_token`**。

所以正确的观测协议是**成对提交**：

```
循环：
   ta = tok_of(Car_X, Berth)      # 该车当前有没有可用凭证
   tb = tok_of(Car_Y, Berth)
   if ta and tb:                  # 两车同时有凭证
       report(Car_X); report(Car_Y)   # 立刻成对提交
       if level >= 3: break
   等待 1 s（凭证有效期 30 s，足够）
```

> m93 实测：这个协议让 `Berth_B` 从 `lv0` 直接跳到 **lv3、unlocked 2/2**。

#### (2) 站位与朝向（实测唯一可行姿态）

| 泊位 | 观测车 1 | 观测车 2 | 说明 |
|---|---|---|---|
| Berth_A | 交付车在 (634.4,−60.8) 朝南 | (641.0,−57.6) | 两车间距 7.0 m |
| Berth_B | 交付车（Car_B）在车位内 | **Car_A 在 (826.0,−65.7) 朝东** | 北/东/南都被挡；探针 pb1 只有 c5 点能拿到 token |

- 朝向要求：目标落在**车头前方 120° 视场**内；朝北/朝南都会 `visible=[]`。
- 站位不能用「单点 `drive_polyline`」去微调（会过冲绕圈）⇒ **把站位点直接并进路线的最后一段**。

#### (3) 交付（deliver）四条件

1. `lv3/precise`，且 `shared_task_objects[berth].position` 就是**精确点**（A=(629.47,−66.72)、B=(834.47,−65.72)）；
2. 该车**已完成中央路口通行**；
3. 距精确点 **≤3 m**（实测 1.15 m 最稳）；
4. **`GearMode.PARKING` + `brake=1.0` 连续静置 ≥2 s**（`|v|<0.05`）。

> m93/m94 的失败就是第 4 条：交完 A 之后车还在微动，`deliver` 六连全部 `must hold a stable position`。
> **解决**：`deliver` 循环里**每次都先强制发 6×`PARKING+brake=1.0`（1.2 s）再交**，而不是只在前置调用一次 `park_and_hold`。

#### (4) 泊位分工

- 一辆运输车只能交一个泊位 ⇒ Car_A↔Berth_A、Car_B↔Berth_B。
- Car_A 交完 A 后要**掉头 + 让出泊位口**才能给别人腾路：`back_out()`（倒车 0.35 油门）→ `turn_around()`（三点掉头）→ 沿 `y=−46.2` 东行。

## 三、并行调度表（这是提效的核心）

| 时刻 | Car_A（运输） | Car_B（运输） | Car_C（巡检） | Car_D（巡检） |
|---|---|---|---|---|
| 0~45 s | 预就位 → 路口南口 (731,−31) | 预就位 → 路口北口 (728.8,6) | 去海关闸口 | 去路障旁 (742,−86) |
| 45~175 s | 停在入口待命 | 停北口待命 | 交 A → 去 B → 交 B → 去 C → 交 C | 停在路障 10 m 内待命 |
| 175~185 s | 待命 | 待命 | 停稳，`scan` 路障（160） | 待命（备用扫描车） |
| 185~280 s | 申请→穿闸口→release（100） | 等路口空闲后同样（100） | 去 Berth_A 北侧观测位 | 去 Berth_B 西侧观测位 |
| 280~400 s | 与 Car_C 成对观测 A → 交付 A（200） | 进 B 车位 | 作为 A 的第二观测车 | 作为 B 的第二观测车 → Car_A 也可替 |

- 路口是**互斥**的（`intersection_owner`），只能接力；但两车**同时就位**，交接只需 0 次赶路。
- 两个泊位的**观测**可并行；`deliver` 一车一位、互不影响。
- 观测车选择：**谁的站位先到就用谁**（规则允许任意两辆不同车），不必固定 Car_D。

## 四、要改的代码（在现有 `fog_mission.py` 上）

| 位置 | 现状 | 改成 |
|---|---|---|
| `main()` 阶段顺序 | 信号→扫描→路口→泊位 全串行 | `stage_prepos()` 先并行预就位（**已加**），其余阶段按事件推进 |

## 六、失败恢复（每条都对应一次踩过的坑）

| 现象 | 根因 | 处理 |
|---|---|---|
| 车原地不动、`[stall]` 刷屏 | 目标点在车后/偏离车道 | 先 `turn_around()`；路线只走车道中心线 |
| `visible=[]` | 车头没对着目标（±60° 外） | 站位点直接并进路线末端，别用单点微调 |
| `但无凭证` | 该车在本等级已交过 | 换另一辆车交（`tok_of` 门控） |
| `Destination is still fuzzy` | 等级 <3 | 先做成对观测 |
| `must hold a stable position` | 没停稳 | 每次交前强制 PARKING+brake 1.2 s |
| `Mission has ended` | 归零或 600 s 到 | 查四类归零；优先查是否进了 6 m 区/封闭带 |
| 客户端起不来 | 上局进程残留 | 杀 `SmartCar`+`metapower_desktop`，等 12 s 重试 |
