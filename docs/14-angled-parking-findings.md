# 异形车道泊车 · 实测与规划结论（2026-10-24 晚）

> 本文只记录**在仿真里实测到的数据**和**离线验证过的结论**，不含推测。

## 一、倒车转向标定（已在仿真中实跑）

脚本 `tools/probe_reverse.py`，场景「异形车道泊车」，倒挡油门 0.13：

| 段 | steering | dyaw（数学系） | 平均速度 | 曲率 κ | 半径 R |
|---|---|---|---|---|---|
| 1 | **+1.0** | **+113.1°** | 7.13 m/s | 0.1834 | **5.45 m** |
| 2 | −1.0 | +11.0° | 1.80 m/s | — | 不可信（车已被第一段顶住） |

**结论**：倒车 `steering=+1.0` → 场景 yaw **减小**（车头左摆）。等效 `κ = 0.1834 × steering`（倒车）。

与已满分 210 的 `tools/park_cs_single_arc.py` 一致：那里 `REVERSE_STEER_SIGN=-1`，
`steering = -1 × heading_error/30`，`heading_error = slot.ori_z - yaw`，
展开即 `steering ∝ (yaw - slot.ori_z)` —— 与标定同号。**倒车符号至此定死，不要再猜。**

## 三、v4 撞车的真正原因

`static.route`（赛道，33 点）在车位附近**拐进了停车区**：

```
( -6.60, 26.98) ... ( -8.82,  0.14) ( -8.90, -0.87) ( -8.98, -1.88)
```

y 越小 x 越负，到 y=-1.9 时 route 已经到 x=-8.98，正好压在车位中心 (-8.48,-2.04) 上。
v4 拿 route 当骨架，必然压路缘/撞边界。

另外 **A 车外角在 (-6.31, -4.55)**，而自车初始就在 x=-6.35 —— 行车线本身与 A 车重叠 0.04 m。
**沿 x=-6.35 直行到 y≈-4.5 一定会碰 A 车**，必须在接近前先右移到 x≈-4.9。

## 四、按车宽（4.81×2.18）量出来的通道宽度

只按车心算会得出错误结论，必须用车体四角。实测三条车道线：

```
lane24  x ∈ [-10.95, -7.45]   宽 3.50
lane22  x ∈ [ -7.29, -3.78]   宽 3.50   ← 自车行驶车道
lane23  x ∈ [ -3.78, +0.02]   宽 3.81
                                   ↑ +0.02 是双向车道中心线（压了扣分）
```

| 量 | 值 |
|---|---|
| 两辆停放车最靠通道的角 | A: x = -6.31，B: x = **-6.29** |
| 通道净宽（B 车角 → lane22 左线 -3.78） | **2.51 m** |
| 自车宽 | 2.18 m |
| **总余量** | **0.33 m**（单侧 0.165 m） |
| 车心允许范围 | **x ∈ [-5.20, -4.87]**，只有 0.33 m 窗口 |

这就是"理论上只剩 0.3 m"的准确来源。

**按车角校核发现的关键错误**：第一版 A*（只约束车心）摆头时车体最右角到了 **x=+1.53**，
越过对向中心线 1.5 m——实跑会吃压线罚分。必须直接把**车体四角**作为约束：

```python
corners = obb(x, y, ori, 4.81, 2.18)
if max(c[0] for c in corners) > -0.05:   # 留 5 cm 余量
    reject
```

## 五、可行性结论（离线 hybrid A*，已跑通）

用实测车体 4.81×2.18、OBB 碰撞（含两辆停放车）、运动学 κ=0.1834、换挡代价，
从 `(-4.9, 3.0, 90°)` 搜索到「车心距车位中心 ≤0.30 m、航向 21.3°±6°」：

**存在可行轨迹，25 点，单次换挡**（先前进摆头，再倒车入位）：

```
FWD: (-4.90, 3.00) 直行至 (-5.24,-1.89)，沿车道中心
     → 边前进边左摆至 (-2.85,-6.16)，航向 93.7° → 51.0°
REV: (-2.85,-6.16) → (-8.32,-1.95)，航向 51° → 20.1°
```

按车体四角校核的指标（`MARGIN=0.10`）：

| 指标 | 值 |
|---|---|
| 车体角 ↔ A 车最小间隙 | **0.207 m** |
| 车体角 ↔ B 车最小间隙 | **0.141 m** |
| 车体最右角最大值 | **-0.488 m**（距对向中心线还有 0.51 m） |
| 终点距车位中心 | **0.181 m** |
| 换向次数 | **1 次** |

**重要**：这不是"一把轮"能进的车位。单圆弧倒车（R=5.26）在任何起点都会让车尾扫进 A 车；
离线扫描表明要走单圆弧不碰撞，半径得放到 **R≥20 m**、起点退到 (2.5,-21.9)，不现实。
加"只在本车道内"走廊约束（x∈[-7.3,-3.8]）后 A* 搜完 20 万节点**无解**——
**必须借相邻车道 lane23**，这是团队前 8 种方案都没试过的路子。

### 加速度奖励分（+10）还没拿到

逐帧差分统计（排除换挡帧、速度过零帧）：

| 版本 | \|a\|>5 的帧数 | max\|a\| |
|---|---|---|
| bang-bang 速度环 | 168 | **21.7** |
| PI + 油门刹车互斥 + 刹车封顶 0.10 | 44 | 10.9 |
| 再加 0.0004/帧油门斜率 + 刹停后挂 P | **8** | **9.2** |

剩下 8 帧的共同特征：**平台回传的 `car.speed` 本身以约 0.2 m/s 的台阶跳变**
（实测 1.57→1.76、0.94→1.17、1.22→1.43），30 Hz 差分必然给出 6 m/s² 以上。
这不是控制量能压掉的——油门当时只有 0.011~0.016，甚至为 0。

排行榜上前 11 名都是 210.00，说明**这个场景确实发这 10 分**，只是还没找到门道。
下一步怀疑方向：平台大概率不是按 30 Hz 逐帧差分，而是按它自己的控制周期（0.2 s）
或对速度做滤波；真正卡住 +10 的可能另有原因（例如换挡帧的正负跨零）。
建议下一步先抓 `HOLD`/换挡瞬间的平台内部日志，而不是继续调控制。

### 速度环踩过的三个坑（都已修）

1. **油门和刹车同时踩**：PI 输出换向时两边都在爬坡，0.4 s 内掉 2 m/s（−8 m/s²）。
   现在强制互斥。
2. **车还在动就挂 P 挡**：v=−0.45 时切 PARKING，两帧内速度归零，+7.2 m/s²。
   现在先刹到 |v|<0.05 再挂 P。
3. **油门斜率太大**：平台"油门→稳态速度"是快跟随，油门从 0.005 爬到 0.05 只要 1.5 s，
   车速就从 0.6 蹿到 1.6。斜率降到 0.0004/帧后起步段 max|a| 从 21.7 降到 1.8。
