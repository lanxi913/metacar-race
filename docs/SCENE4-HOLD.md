# 强制停车（HoldController）—— "必须停就一次停住"

> 需求来源（2026-10-25，用户原话要点）：「遇到必须停车的时候，搞成强制停车，不要那种
> 顿顿卡卡的；要有前瞻性，前面有车阻挡就提前减速、然后停住，除非车走了再走。」

## 1. 为什么原来的"停车"会顿挫

p4 / p5 两趟元素 8（车辆紧急停止）的逐帧数据把原因摊得很清楚，是三件事叠在一起：

1. **刹车被当成调速手段。**
   `brk` 在平台里是"制动指令"，`a_cmd = 8·throttle − 100·brake`。`brk=0.35` 一帧就是
   `a_cmd = −35`，车端实测 −13~−18 m/s²；而 `brk=0.05` 正好是 `a_cmd = −5`，卡在预算线上。
   → p4 元素 8 有 **114 帧 `|a|>5`、809 帧刹车**，全来自这个口径。
2. **到位了还在推。**
   旧逻辑里"安全车速剖面"给出 `v_kin = sqrt(2·a·d_free)`，到了 `d_free=0.8 m` 仍然给
   1.3~1.5 m/s，于是速度环给油、安全闸刹、再给油——原地"窜—憋—窜"。p5 就是这样从
   5.9 m 蹭到 4.9 m（最后那 0.1 m 位置误差也是它造成的）。
3. **纵向环的积分顶住减速。**
   PI 攒的积分先顶住减速，等目标断崖变 0 时再一拍到底，于是出现"刹—窜—刹"的双尖峰。

## 2. 现在的做法：一个状态机说了算

`metacar_race/scene4/holdctl.py`，一帧一次 `update()`，返回 `HoldCmd(mode, v_cap, lock, bite)`：

```
run ──(前方有阻挡，按运动学剖面提前收速)──> decel
  ──(进到目标停车点余量内 / 已经慢到可以锁)──> hold（P 挡 + 满刹）
  ──(前车拉开 3 m 且稳定 1 s)──> release（一次咬合油门）──> run
```

关键参数（`scene4/config.py`）：

| 常量 | 值 | 含义 |
|---|---|---|
| `HOLD_BRAKE` | 0.05 | 锁定过程中的刹车（`a_cmd=−5`，不许再大） |
| `HOLD_LOCK_MS` | 0.12 | 车速低于它才挂 P 挡（0.12/0.033≈3.6 m/s²，压得住） |
| `HOLD_LOCK_EXTRA` | 0.35 | 距目标停车点这么近就锁定，不再往前蹭 |
| `HOLD_LOCK_WINDOW` | 1.20 | 已经趴慢时，距目标点这么近就锁定 |
| `HOLD_RELEASE_M` | 3.00 | 前车拉开这么远才算"路让开了" |
| `HOLD_RELEASE_S` | 1.00 | 并且要稳定这么久（防前车晃一下被当成放行） |

## 3. 三个"前瞻性"设计点

- **前瞻用时间/运动学，不用固定距离。** 旧代码 `dist < 7 m` 才动手，7 m 处 7 m/s 需要
  4.2 m/s² 才停得住，必然急刹。现在按 `v_kin = v_lead + sqrt(2·a·(d_free − extra))`
  从 30 m 就开始收，全程只有一段减速。
- **停车点用相对量。** 元素 8 的目标是"后车中心距前车中心 5 m"，所以 `stop_gap` 取
  前车**中心**距离（`EMERGENCY_STOP_GAP_M = 5.00`），不是路线里程；其它元素退
  `BLOCK_STOP_GAP_M`（6.3 m = 4.8 车头余量 + 1.5 停车余量）。
- **放行要防抖，放行后要"咬合早"。** 只有 `dist > stop_gap+3 m` 且持续 1 s 才放行；
  放行那一帧直接给 `LAUNCH_THR=0.15` 的咬合油门——把"离合咬合那一下"从判分区中段
  挪到刚放行的头两帧（场景起点起步的实测结论：0.20 s 咬合 → 210，0.60 s → 200）。
