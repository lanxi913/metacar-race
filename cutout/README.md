# 车辆切出（场景元素 27）

> 基础 100 分 + 全程 `|a| ≤ 5 m/s²` 的 10 分 = **110 分**。
> 本分支 `feat/cutout`，控制器在 `cutout/main.py`（与 `merge/main.py` 同一套骨架）。

## 1. 规则（评分规则 docx 表 27）

| 项 | 内容 |
|---|---|
| 目标 | 1. 起点开到终点；2. **车辆切出，终点与起点不在一条道路上** |
| 超时 | 200 s 内没完成 → 0 分 |
| 压线 | 行驶过程中压线 −20 分 |
| 特殊 | **车辆到达同一车道的终点不视为结束场景** —— 必须真的切出去到另一条道路 |
| 本场其它因素 | 没有对手车、没有信号灯、没有停止线（探针 40 帧确认），所以唯一扣分项就是压线 |
| 加分 | 全程 `|a| ≤ 5 m/s²` 另加 10 分（平台「加速度控制」） |

示意图（docx image27）：主路右车道向右分出一条实线弯道，末端蓝色虚线是终点 ⇒ 「切出」＝驶离原车道进入另一条道路。

## 3. 本场与「车辆汇入」的差别

- 场景包 `cheliangqiechu/SmartCar_Data/StreamingAssets/mapfile/` **确有** `route` + `mapd`（`find_scene_mapd` 用路线指纹以 0.000 m 误差认出来），所以中线化代码照样跑。
- 但这份 `mapd` 是整个大地图（**926 条边界线段**），`corridor_offsets` 在 0.5 m 重采样后成对取最近左右边界时会被邻近道路干扰：原始修正量分布 **−1.74 ~ +1.81 m，46 个点里 23 个 |修正| > 1.0 m**，被 `cap=1.2` 截断。
- 实测结论：**中线化在本场不是必需的**。`--no-center`（直接跟 route）同样 **110.00**；中线化版实际行驶轨迹相对 route 最大横偏 **0.93 m**（t=3.8 s）、平均 0.23 m，也没压线。
  ⇒ 说明这条 route 本身就基本走在车道中线，与「车辆汇入」匝道段偏 0.80 m 的情况不同。**换场先量，别照搬上一次的结论。**

## 4. 控制律（`cutout/main.py`）

- 横向：纯跟踪，前视 `Ld = clamp(1.2v + 2, 4, 14)` 再按局部曲率封顶 `0.55R + 1.5`；
  `delta = atan(2·left/dist²·WHEELBASE)`、`steer = −delta/MAX_STEER`。
  （默认 `--steer pure`；`--steer stanley` 留作对照。）
- 纵向：加速度空间 PI —— `KP=1.0 / KI=2.0 / A_ACC_MAX=2.0 / A_ACC_SLOW=1.4 / A_DEC_MAX=1.8`，
  油门/刹车按实测增益换算（油门 ≈150 m/s²每单位、刹车 ≈32 m/s²每单位）。
- 起步：`car.speed < 0.5 且 v_cmd > 1.0` 时 `thr ≥ LAUNCH_THR=0.15`，让离合在 ~0.2 s 内咬合
  —— 本场起步尖峰 `15.78@0.167s / 14.88@0.200s / 12.45@0.233s` 全部落在平台豁免的最初 0.5 s 内。
- 终点：沿路线越过终点 `END_PAST=2 m` 后摘挡 + 刹车斜坡；实际场景在车头越过终点区时由平台结束（`arrived=false` 但成绩照记）。
- 防误判：不按「到同一车道终点」结束 —— 终点判定只用 `sub_scenes[0].end_point`，符合表 27 第 3 条。

## 7. 未覆盖 / 待改进

1. 中线化在本场的大地图上会被邻近道路干扰（见第 3 节），目前靠 `cap=1.2` 兜住；若要更稳，应改成「按当前车道索引取边界」而不是全局最近边界。
2. 平台在车头进入终点区时自动结束（`arrived=false`），脚本自己的 `END_PAST` 收尾没机会触发；换成更长的尽头路场景需要用 `--seconds` 兜底。
3. 本场没有车流，**切出时的目标车道后方来车判定没机会验证**；若换成有车版本，需要补「切出前看后视盲区」的判定（可复用 `leftturn` 的相邻帧差分测速）。
